🧠 Visão Geral

O Local Triage Agent é um componente determinístico de atendimento de suporte de TI que:

✅ Classifica intenções dos usuários
✅ Extrai campos obrigatórios
✅ Valida com regras estritas
✅ Solicita informações que faltam
✅ Gera JSON final pronto para abertura de chamado

Premissas-chave:

É um sistema fechado, conforme DMD v2.1

Não aprende / não evolui sem novo ciclo de governança

Comportamento determinístico por máquina de estados

Separação clara entre core (triagem) e integração (GLPI)

📌 Premissas Operacionais
Item	Descrição
Usuário	Perfil leigo, sem jargão técnico
Identificação	Aceita apelidos (“impressora do RH”)
Enriquecimento	Dados técnicos via automação externa
Diagnóstico	L1 apenas coleta, não resolve
Gerenciamento	Regido pelo Documento Mestre de Decisão v2.1
🚦 Mapa de Intenções
Intenção	Descrição	Escopo
RESET_PASSWORD	Esquecimento ou bloqueio de senha	AD / Rede / E-mail integrado
CREATE_USER	Criação de identidade digital	RH/TI
EQUIPMENT_REQUEST	Solicitação de ativo físico	Incidente ou Requisição
PRINTER_ISSUE	Problemas de impressão	Impressoras departamentais
VPN_ACCESS	Concessão de acesso remoto	VPN/Cliente
CORPORATE_SYSTEMS	Erros em sistemas corporativos	ERP/CRM/Legados
🔢 Schemas de JSON — Modelos de Dados

Todos os resultados do agente devem seguir os schemas abaixo, validáveis por Pydantic ou Zod.

Estrutura final combinada de saída:

{
  "intent": "STRING",
  "is_complete": true | false,
  "ticket_payload": {
    // Campos específicos por intenção
  },
  "missing_fields": ["field1","field2"],
  "diagnostics": null | { /* detalhes extras */ }
}

🧩 Regras por Intenção
🛠 RESET_PASSWORD

Objetivo: Resetar senha de acesso

Campos obrigatórios:

usuario_rede

sistema_afetado

Regras de fronteira:

Se não mencionar sistemas corporativos específicos, assume “Rede/Windows” por padrão.

🧾 Payload JSON
{
  "intent": "RESET_PASSWORD",
  "is_complete": true,
  "ticket_payload": {
    "usuario_rede": "jose.silva",
    "sistema_afetado": "Rede/Windows"
  },
  "missing_fields": [],
  "diagnostics": null
}

👤 CREATE_USER

Objetivo: Solicitar criação de nova identidade digital

Campos obrigatórios:

nome_completo

setor

tipo_usuario

identificador_condicional

Identificador condicional:

Efetivo → CPF OBRIGATÓRIO

Estagiário → RG OBRIGATÓRIO

Terceiro → Matrícula OU Empresa

📌 Payload JSON
{
  "intent": "CREATE_USER",
  "is_complete": false,
  "ticket_payload": {
    "nome_completo": "Maria Oliveira",
    "setor": "Contabilidade",
    "tipo_usuario": "ESTAGIARIO",
    "rg": null,
    "cpf": null,
    "empresa": null
  },
  "missing_fields": ["rg"],
  "diagnostics": null
}

🖥 EQUIPMENT_REQUEST

Objetivo: Solicitar equipamento físico ou relatar falha

Campos:

item

request_type → incident | requisition

description (se incident)

quantity (se requisition, opcional, >=1)

📌 Exemplos JSON

Caso Incident

{
  "intent": "EQUIPMENT_REQUEST",
  "is_complete": true,
  "ticket_payload": {
    "item": "Mouse",
    "request_type": "incident",
    "description": "O mouse não está respondendo",
    "quantity": null
  },
  "missing_fields": [],
  "diagnostics": null
}


Caso Requisition

{
  "intent": "EQUIPMENT_REQUEST",
  "is_complete": true,
  "ticket_payload": {
    "item": "Monitor",
    "request_type": "requisition",
    "description": null,
    "quantity": 2
  },
  "missing_fields": [],
  "diagnostics": null
}

📠 PRINTER_ISSUE

Objetivo: Resolver problema de impressão

Campos:

location_description

issue_summary

Não pedir IP, caminho de fila, patrimônio físico, nem jargões técnicos.

📌 JSON
{
  "intent": "PRINTER_ISSUE",
  "is_complete": true,
  "ticket_payload": {
    "location_description": "Impressora do RH, 2º andar",
    "issue_summary": "Sem toner e não imprime"
  },
  "missing_fields": [],
  "diagnostics": null
}

🔒 VPN_ACCESS

Objetivo: Conceder acesso VPN ou instalar cliente

Campos:

justification

Regras:

Não cria usuário de rede

Se não existir usuário, orientar CREATE_USER primeiro

📌 JSON
{
  "intent": "VPN_ACCESS",
  "is_complete": true,
  "ticket_payload": {
    "justification": "Preciso acessar sistema remoto para auditoria."
  },
  "missing_fields": [],
  "diagnostics": null
}

💻 CORPORATE_SYSTEMS

Objetivo: Relatar erro em sistema corporativo

Campos:

system

error_message

📌 JSON
{
  "intent": "CORPORATE_SYSTEMS",
  "is_complete": true,
  "ticket_payload": {
    "system": "SAP",
    "error_message": "Erro de login no módulo financeiro"
  },
  "missing_fields": [],
  "diagnostics": null
}

🔁 Fluxo Determinístico de Estados
Start
  ↓
Router → [Classifica intenção]
  ↓
Extractor → [Extrai campos]
  ↓
Validator → [Completo?] —→ Inquiry (se faltou)
             |                               ↓
             |                      Validator (revalida)
             ↓
        JSON Final Output

📌 Regras de Inferência
Caso	Regra
Datas vagas	Converter para datas reais
“Velho/gasto” em equipamento	Inferir requisition
Pronomes	Associar ao objeto anterior
Urgência implícita	Média por default
Impacto implícito	Individual por default
🚨 Confirmação & Handover

Limite de 3 tentativas por campo

Depois = Handover N2

Se divergência persistente = Handover

Se intenção ambígua = Handover
